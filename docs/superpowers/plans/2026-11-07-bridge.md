# Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make a first-person ship bridge the default Home, with the existing universe as its window and real work panels around it.

**Architecture:** `Bridge.tsx` renders a fixed stage (CSS/SVG frame, no raster art), panels bound to `/universe/objects`, and embeds the existing `Cockpit` in a new `windowMode` so camera, WebGL, labels, picking, ObjectCard and deep links are reused unchanged. Layout, parallax, warp timing and panel data are pure modules under `apps/web/src/bridge/`.

**Tech Stack:** React 18, TypeScript, vitest + jsdom + Testing Library, existing WebGL renderer.

**Spec:** `docs/superpowers/specs/2026-11-07-bridge-design.md`

## Global Constraints
- Simple mode keeps four anchors; no note-taking features; classic Cockpit stays selectable (`homeView: "classic"`).
- Reduced motion (`settings.reduceMotion === "on"` or `prefersReducedMotion()`): no parallax, no streaks, crossfade only.
- Warp is 1500 ms (250 ms reduced), dolly only, skippable with Esc or a click on the window.
- Phone is under 600 px; TV/car targets are at least 48 px; parallax is off on phone and TV.
- Only the Alerts wall uses strong red/amber and pulsing.
- Every `destinations()` entry is reachable from the holo-table.

## Review Focus
- Zero objects / server error: bridge shows an honest empty state, not a crash.
- Engage with nothing selected does nothing.
- Esc mid-warp finishes navigation exactly once (no double navigate).
- Unknown/stale deep link id: bridge still renders.
- Pointer events on panels must not orbit the window camera.
